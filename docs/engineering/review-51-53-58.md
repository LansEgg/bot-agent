# Review remediation: reply gate, SQLite, tool deadlines

## Objective and scope
Resolve issues #51, #53 and #58 without changing tenant FIFO, model routing,
or the .NET 8 target. Use only synthetic fixtures. No deployment or publication.

## Pre-remediation architecture and impact
ReplyPipeline captures a SemaphoreSlim before waiting, but ResizeGate disposes
the old instance after a fixed 90 seconds regardless of holders or waiters.
ToolCircuitBreaker only passes a cancellation token to operations, so ignoring
that token returns late success. Microsoft.Data.Sqlite 8.0.10 resolves a vulnerable
native SQLite dependency; CI currently builds without an audit failure gate.

## Contracts and data flow
Replace timer retirement with an internal reference-counted gate lease. Capture
and reserve a lease under the same lock as gate replacement. Count both holders
and waiters; dispose retired semaphores only after the final lease is released.
Existing admitted requests drain on the old generation; new requests use the new
generation (there can be temporary overlap, as before).

ToolCircuitBreaker bounds the caller's await independently of cooperative
cancellation. Request cancellation on deadline and observe late faults without
allowing late completion to mutate circuit state. This is not process isolation:
an uncooperative underlying operation may continue and have external side effects.

The follow-up review found that disposing the invocation CTS at the end of the
bounded await was still unsafe: work could remain pending and queued cancellation
callbacks could be skipped. The CTS is now owned by one asynchronous cleanup task.
Caller cancellation is bridged into one memoized `CancelAsync` request instead of
a linked CTS, so operation callbacks cannot block or throw from caller `Cancel`.
Cleanup unregisters the caller bridge, observes work and cancellation-task faults
independently, waits for **both** to settle, then disposes the CTS. It never invokes
`RecordSuccess`, `RecordFailure` or `RecordTimeout` after the caller result is fixed.
If work or a callback never completes, its CTS remains owned until it can safely
be reclaimed; this deliberately does not promise forced interruption or a bound
on underlying work/resource lifetime.

Gate leases are single-use reservations: await `WaitAsync` (including cancellation
or failure) before disposing the lease. The production reply path follows that
contract in its `finally`; concurrent early `Dispose` while a wait is still active
is not a supported lease usage. Resizing affects newly reserved requests only.

Upgrade Microsoft.Data.Sqlite within 8.0, verify transitive native resolution and
runtime SELECT sqlite_version(). Restore audit fails for High/Critical using
NuGetAuditLevel and NU1903/NU1904 as errors; ordinary compiler warning policy stays.

## Follow-up review and actual evidence

### High severity, fixed: premature CTS disposal

In [ToolCircuitBreaker](../../src/BotAgent.Headless/Services/Resilience/ToolCircuitBreaker.cs),
the first deadline fix used `using var timeoutCts` while abandoning pending work
and calling `CancelAsync` without waiting for callback completion. This left late
work with a disposed token source and could clear callback registrations before
they ran. The expanded
[DeadlineGateProbe](../../tests/BotAgent.DeadlineGateProbe/Program.cs) reproduced
**44 passing / 9 failing** assertions, exit 1, against the already-compiled baseline.
Both deadline and external-cancel callbacks were skipped; the token's wait handle
was already unusable while work or callbacks were still pending. The initial
12-assertion baseline had passed and did not cover this lifetime defect.

The post-fix probe ran with its **normal ProjectReference**, rebuilding the real
core source: **53 passing / 0 failing**, exit 0. Three subsequent `--no-build`
repetitions of that newly built binary also returned **53 / 0** each. Baseline
`-p:BuildProjectReferences=false` was used only for the red observation, not as
evidence that changed source was compiled. No source-linked bypass was used.

The added cases cover blocked cancellation callbacks on deadline and external
cancellation, callback exceptions, token usability while work and callbacks are
pending, eventual CTS disposal after both finish, late success/fault state
stability, and late-fault reclamation. The probe uses barriers and synthetic
completion sources, not a new clock abstraction or production data.

### Gate reservation review: no follow-up source changes needed

[ResizableReplyGate](../../src/BotAgent.Headless/Services/Reply/ResizableReplyGate.cs)
and [ReplyPipeline.HostAccess](../../src/BotAgent.Headless/Services/Reply/ReplyPipeline.HostAccess.cs)
retain the generation/reservation design. The added **19 gate assertions** passed
in both red and green runs: canceled and pre-canceled waiters release references
without releasing an unacquired permit; the final retired lease actually closes
the old `SafeWaitHandle`; unused reservations protect and release old generations;
duplicate disposal is idempotent; same-size resize is inert; invalid constructor
and resize counts (-1, 0, 17 and Int32.MaxValue) are rejected without swapping the
generation. Repeated concurrent resizing/reservation still passes. This review
does not change permit policy, per-tenant FIFO or the temporary overlap between
draining old generations and a new gate.

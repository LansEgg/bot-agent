## 4. Compatibility decisions and residual risks

1. **Feishu new-map/legacy isolation is intentional.** Back up the new `data/feishu-ids-v2.json` alongside application data when an authorized upgrade is performed. Existing sessions, old 32-bit aliases and numeric whitelist entries are retained but not guessed into native bindings or inherited history; numeric whitelist entries require reconfiguration to native IDs. An absent map is treated as fresh, so startup cannot distinguish first use from a deleted map: existing v2 aliases without bindings cannot be reverse-routed, while later native events may allocate typed deterministic bindings again. Only an existing corrupt map is rejected by strict startup loading. Collision protection depends on the retained ledger; restore a backup instead of deleting the file and losing recorded bindings, and never infer legacy 32-bit mappings. One production gateway owns the store; concurrent multi-process writers are unsupported. The numeric bridge includes app identity, but structured ingress still keeps its existing `default` account scope; no full account-scope redesign is claimed.
2. **Feishu hot reload does not interrupt existing sends.** Queued/in-flight old snapshots may finish using their captured old account/endpoint; later requests use the new snapshot. Identity allocation and dedup registration are safer, but callbacks and dedup still are not an exactly-once transaction. Callback failure after registration retains the documented residual risk.
3. **Own-message compatibility is fail-closed, not a guessed migration or lossless downgrade.** The additive scoped table preserves platform/account/target/kind/thread/native-ID identity. Legacy bare-ID rows and archived JSON are retained but never become scoped hits; bare-ID compatibility writes do not reconstruct scope. An old binary cannot consume the new scoped records. Retain a pre-upgrade backup; no dual-write or lossless downgrade is promised.
4. **Settings/audit atomicity has explicit limits.** Supported settings and SQLite audit persistence commit together before publication. Secret-store writes remain independent and may have succeeded before a settings/audit failure. A postcommit runtime/notification callback can fail and return non-success after disk and the published snapshot already changed; committed state is not rolled back, and some dependents may require retry/rebuild. Mood/TTS side effects run after successful settings commit but are not a cross-store atomic transaction.
5. **Hard timeout bounds the caller, not underlying effects or resources.** Cancellation is requested and faults are observed, but uncooperative work may continue and produce external side effects. CTS remains owned until work and cancellation callbacks both settle; a never-completing path can retain it indefinitely. Thread-pool/runtime scheduling is not real-time scheduling or process isolation.
6. **Gate generations can temporarily overlap.** Existing reservations drain on their original gate; new reservations use the resized generation. This is not a retroactive global permit cap across generations. Leases are single-use: await the wait outcome before `Dispose`; disposing concurrently with an unfinished wait is unsupported by the production usage contract.
7. **Network/process fixes are scoped, not blanket isolation.** Trusted configured model/internal clients remain separate from hardened untrusted-URL fetchers; the explicit private-image-host override remains available. POSIX descendants can deliberately escape an owned process group via a new session. The reverse transport remains a minimal RFC6455 implementation; frame hardening is outside this issue scope, and a full pending-handshake cap can require legitimate retries.
8. **Helper implementation does not imply runtime feature enablement.** Jargon panel CRUD is wired, but Jargon observation/discovery/prompt rendering has no runtime consumer. Episode extraction/recall and versioned prompt runtime/rollback are not wired. Health reports are currently wired to the OneBot gateway, not a verified multi-channel health delivery path. These boundaries are documented rather than silently enabled by this remediation.
9. **Coverage exclusions remain visible.** S42 was not run and is excluded from harness/CI; S2 is inside S1. Synthetic Feishu, official-alias gating and manual browser checks are not production transport acceptance. No production or remote CI success is claimed.
